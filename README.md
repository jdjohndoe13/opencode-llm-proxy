# LLM Proxy (nginx + njs)

A small reverse proxy built on the official `nginx:alpine` image that sits in
front of an LLM backend. It listens on port **9999** and forwards everything to
the backend configured via the `LLM_BACKEND` environment variable (default
`192.168.1.3:1025`), with one special case:

For every request to **`/v1/completions`** or **`/v1/chat/completions`**
(a JSON object body), the proxy rewrites the request body by setting:

- `top_p` → `0.95`
- `stream` → `false`

and then passes the modified body to the backend at the same path.
All other paths are proxied unchanged.

## Files

```
.
├── docker-compose.yaml              # service definition + LLM_BACKEND env var
└── nginx/
    ├── nginx.conf                   # main config: njs module, logging, buffer sizes
    ├── templates/
    │   └── default.conf.template    # server block (envsubst at startup)
    └── njs/completions.js           # njs handler that rewrites the JSON body
```

## Requirements

- Docker with Docker Compose
- The LLM backend must be reachable at the address set in `LLM_BACKEND`

## Configuration

The target backend address is an environment variable in `docker-compose.yaml`:

```yaml
environment:
  LLM_BACKEND: 192.168.1.3:1025
```

At container startup, the official image's `20-envsubst-on-templates.sh`
entrypoint replaces `${LLM_BACKEND}` in
`nginx/templates/default.conf.template` and writes the result to
`/etc/nginx/conf.d/default.conf`. To point the proxy at a different backend,
change `LLM_BACKEND` and restart:

```bash
docker compose up -d --force-recreate
```

## Usage

```bash
docker compose up -d
```

The proxy is then available at `http://localhost:9999`.

Example (completions):

```bash
curl http://localhost:9999/v1/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-3.5","prompt":"Hello","top_p":0.3,"stream":true}'
```

Example (chat completions):

```bash
curl http://localhost:9999/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-3.5","messages":[{"role":"user","content":"Hello"}],"stream":true}'
```

The backend receives the body with `top_p: 0.95` and `stream: false` and
responds non-streaming.

Stop the proxy:

```bash
docker compose down
```

## How it works

The stock `nginx:alpine` image already ships the njs module
(`ngx_http_js_module.so`), so no custom image is required — the config only
loads the module and mounts the njs script.

1. `nginx.conf` loads the module and imports `completions.js`.
2. At startup the entrypoint expands `${LLM_BACKEND}` into
   `templates/default.conf.template`, producing the live `default.conf` that
   routes `/v1/completions` and `/v1/chat/completions` to the njs
   `js_content` handler (regex `^/v1/(chat/)?completions$`).
3. The handler reads the request body (`r.requestText`), parses it as JSON,
   forces `top_p: 0.95` / `stream: false`, and re-serializes it.
4. The modified body is sent to the backend via an internal subrequest
   (`/_completions/<original path>`, marked `internal`) that proxies to the
   `llm_backend` upstream at the same path.
5. The upstream response (status code, body, and headers) is returned to the
   client; `Content-Length` and transfer headers are regenerated by nginx.

## Configuration notes

| Setting | Where | Why |
| --- | --- | --- |
| `LLM_BACKEND` | `docker-compose.yaml` | Backend `host:port`; substituted into the config at startup (used for both the upstream address and the `Host` header sent upstream) |
| `client_max_body_size` / `client_body_buffer_size 100m` | `nginx.conf` | Keep request bodies in memory so `r.requestText` can rewrite them (default is ~8k; larger bodies would be spilled to disk and become unreadable) |
| `subrequest_output_buffer_size 32m` | `default.conf.template` | The subrequest response is buffered by njs; the default (~8k) truncates large completions |
| `proxy_read_timeout 300s` | `default.conf.template` | LLM inference can take longer than the default 60s |
| `proxy_set_header Accept-Encoding ""` | `/_completions` | Upstream responses must not be compressed, because njs forwards the buffered (uncompressed) body |

To change the target backend, edit the `LLM_BACKEND` environment variable in
`docker-compose.yaml` (not the nginx config) and restart:

```bash
docker compose up -d --force-recreate
```

## Notes / limitations

- Only `/v1/completions` and `/v1/chat/completions` are rewritten; every other
  path is proxied as-is. The rewrite matches the regex
  `^/v1/(chat/)?completions$`, so other `/v1/.../completions` endpoints would
  need the pattern extended.
- The backend must accept a normal (non-streaming) JSON response — responses
  are buffered in full by the subrequest before being sent to the client, so
  SSE/streaming from the upstream is not supported for these endpoints.
- Invalid or empty JSON bodies on a rewritten endpoint return `400`.
- The `Host` header sent to the backend is the `LLM_BACKEND` address (not the
  original client `Host`), which is fine for LLM backends that don't use
  virtual hosting.
